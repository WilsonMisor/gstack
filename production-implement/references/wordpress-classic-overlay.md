# WordPress Classic Theme + Custom Plugin Overlay

When the Project Contract selects this overlay: classic theme owns presentation; custom plugin owns product/business logic; WordPress core remains the runtime. Block-theme/FSE/Gutenberg-layout/page-builder prohibitions apply only to projects whose contract requires this code-first classic approach.

This overlay does **not** replace the immutable FS-001..FS-075 baseline. It is the one-to-one WordPress interpretation of source rows 1..75. Every WordPress implementation slice must classify the underlying FS control and then use the matching WP row for stack-specific gate/test/evidence. No WP row may be merged, deleted, renumbered, or silently skipped.

## Cross-cutting WordPress enforcement

In addition to the row-specific interpretation above, enforce nonces, `current_user_can`, `map_meta_cap` where resource ownership matters, owner/tenant/role/status checks, scoped `WP_Query`/custom SQL, `$wpdb->prepare`, REST `permission_callback`, private-file authorization, context-appropriate sanitisation/escaping, safe caching, idempotency, cron locking, deployment rollback, recovery evidence, and operational ownership whenever the corresponding source controls apply.

The acceptance rule remains: **no applicable gate, no passing test, no evidence, no acceptance.**
